# context-keeper 技能优化需求文档

**创建日期：** 2026-04-03
**项目：** context-keeper
**功能模块：** context-keeper 技能优化

## 一、需求概述

在现有 context-keeper 技能基础上，增强复盘功能，优化文档结构，提升可用性。

核心需求：
1. 在保存 worklog 时，添加"本次对话复盘"章节
2. 复盘深度根据任务复杂度自动调整（简单任务简要复盘，复杂任务结构化复盘）
3. 快速摘要增加"经验"字段，区分"问题"（事实描述）和"经验"（经验提炼）
4. 创建 `lessons-learned.md` 索引文件，记录每次工作的关键经验教训
5. 加载上下文时，展示近期 3-5 条经验教训
6. 统一文件名格式为 `YYYY-MM-DD-[功能模块]`（去掉时分）

## 二、功能结构

```
保存上下文流程：
1. 分析信息来源 + 判断任务复杂度
2. 推断功能模块名称
3. 生成需求文档
4. 生成工作日志（含复盘章节）
5. 更新 lessons-learned.md 索引
6. 按需更新相关文档
7. 询问是否提交代码

加载上下文流程：
1. 读取最近工作摘要（含"经验"字段）
2. 读取近期 3-5 条经验教训索引
3. 展示给用户
4. 按需加载完整文档
```

## 三、数据来源

- 对话历史：提取需求、决策、问题、解决方案、经验教训
- Git 变更：`git status`、`git diff HEAD`
- 历史经验：`docs/lessons-learned.md`

## 四、技术要求

- 复盘深度分级：
  - 简单任务：1-2 段简要复盘
  - 复杂任务：结构化复盘（5 个子章节）
- 快速摘要字段：
  - 完成、问题（事实描述）、经验（经验提炼）、下一步、文件
- 索引文件：`docs/lessons-learned.md`，按时间倒序排列
- 文件名格式：`YYYY-MM-DD-[功能模块].md`

## 五、设计要求

- 复盘章节清晰：模板中只保留章节标题，具体内容根据复杂度填充
- 字段区分明确："问题"侧重事实，"经验"侧重提炼
- Token 优化：加载时只读索引（~100 tokens），不加载完整复盘
- 通用性：适用于任何项目

## 六、验证标准

- 保存时正确判断任务复杂度
- 简单任务生成简要复盘，复杂任务生成结构化复盘
- 快速摘要包含"经验"字段
- `lessons-learned.md` 正确创建和更新
- 加载时展示近期经验教训
- 文件名格式统一

## 七、参考资料

- 原始需求：用户要求在保存 worklog 时添加复盘功能
- 优化建议：复盘深度分级、快速摘要增加"经验"字段、复盘内容可搜索
