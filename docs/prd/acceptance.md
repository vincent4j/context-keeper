# 验收要求与能力边界 PRD

## 证据标准

配置写入、脚本回归、受控场景和真实宿主行为分别验收。找到记录、实际采用、结果验证有效分别报告。文件存在、哈希匹配、CLI 正常退出、业务测试通过、结构检查通过，均不能替代 Agent 实际加载、触发和语义判断的证据。

当前代码基线 `7d54684` 的上一轮完整脚本回归为160项通过；这是本次文档整理前的历史代码证据，不表示所有宿主或未来版本通过。原过程材料保留在该提交及其祖先中，可通过 Git 恢复；不再打包模型输出、轨迹、快照、过程补丁或本机安装清单。

## 真实新会话验收

使用隔离且已授权的项目，记录客户端版本、实际返回模型信息、自然提示、工具调用、结果及文件差异。不能把显式要求保存或创建经验的结果计为自动触发通过，不猜测供应商真实模型身份，不因为失败调整提示反复重跑后只保留成功。

1. 普通修改不检索；自然历史信号触发有界检索。
2. 两个不同业务入口的独立验证后自然整理经验，新入口复用时保持同一编号，真实样本未验收待办持续保留。
3. 同会话再次保存保留旧日志完整字节前缀，末尾追加；重复输入不重复编号。
4. 经验只有被采用并得到当前结果证据，才在该范围判为复用有效；偏好、一次成功和原样重跑不机械产生经验。
5. 两个真实宿主互换接手，检查实际加载、触发、读取预算、证据判断和写入行为，不以一个宿主成功推广到六家。

## 续接补漏独立场景

A 用2 MB样本确认入口限制修复，当前摘要写“413已解决”；B 用25 MB样本定位并修复上游限制，仅留下日志和索引，摘要和经验暂时滞后；C 新会话仅收到“继续上传413排查”。合格结果区分样本与两层限制、给出两处具体来源并收窄原判断。

还须覆盖：同文件中段出现反证后继续追加其他内容；两个宿主复述同一运行；不同版本或条件不可比；只读续接零改动；同证据再次保存无重复。当前写入前查询不搜索日志，不保证此场景通过；不恢复专用 review-evidence 命令来掩盖尚未验收的结果。

## 已知限制和未验收项

- compact归档区不直接进入search的memory分支，有限回退不保证全召回；索引和日志尾部截取可能遗漏中段反证。有限未命中不能证明历史上没有发生。
- 历史受控Codex CLI场景曾观察到续接、经验整理和跨入口复用，但早期对照也出现自动经验未生成与当前主题漏召回；少量成功/失败不能估算长期可靠率或证明某提交是唯一原因。
- 早期Claude Code/MiniMax-M3场景中，显式保存可用，自然纠正未自动沉淀，读取预算也未严格遵守；不能用后续其他模型或场景的成功抹去该限制。
- 历史本机Codex桌面场景观察到用户级加载和多关键词续接；Claude Code场景观察到加载和经验整理，未观察到resume调用。WorkBuddy用户级单独入口未验证通过，项目桥接场景有成功观察。均不代表本机当前安装状态或所有模型可靠。
- ZCode、DeepSeek Harness和OpenCode的入口配置不等于真实客户端新会话已验收。最新写入前对照的自动触发、语义合并和续接补漏仍待真实会话验证。
- 真实上游样本、生产效果、长期连续使用成功率未验证。突然关闭、崩溃或立即中止不保证补记。
- 通用Skill Creator校验器对既有发布字段有兼容性限制；不删除合法发布字段来换取通过，不把该校验宣称为已通过。
