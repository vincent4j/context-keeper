# 记忆可靠性 PRD

状态：当前需求与最小修正已确认，部分模型行为仅有受控样本证据。本文是记忆可靠性模块的唯一需求入口；不代表全部待办已完成或已正式发布。

本文维护问题、方案依据、功能边界、优先级和验收标准。实验批次、失败轨迹、成本与原始材料已保全至仓库外的历史档案，不作为产品或测试依赖，也不随本模块PRD打包；产品使用步骤以[检索说明](../../references/search.md)和[续接说明](../../references/resume.md)为准。

## 1. 目标与结论

本模块回答：如何让 Context Keeper 在后续会话中找到有用经验、识别过时结论、依据直接证据更新认识，并控制读取和维护成本。

建议保留现有 Markdown、项目隔离、历史日志只追加和按需检索架构。首先验证反证是否可达及是否被正确理解；再根据失败位置，决定调整检索、来源展开或经验规则。暂不引入后台整理服务和新的通用知识库层。

用户要求明确每项建议解决的问题、解决方式、依据、TODO 优先级及理由，并说明不借鉴的内容。未触发的条件项保持暂缓：PRD完成不代表功能已开发、实验已通过或已授权部署。

## 2. 依据及其适用范围

### 2.1 外部依据

唯一外部研究来源为 Anthropic 的 [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)（页面标注发布于 2026-11-06）。相关段落：

- “Dreaming can correct memory”：回查原始会话可纠正错误记忆。
- “Steering Claude to write memory”：不同模型对记忆指导的响应不同，固定限制可能削弱效果。
- “Dreaming can build new memory representations”：Wiki 在部分跨文档任务中有帮助，也可能收益有限或体积膨胀。
- “Dreaming can focus memory on a specific goal”：记忆组织需要服务具体任务，并注意共享文件写入冲突。
- “Thinking backward, looking forward”：整理需要计算成本，更新频率与范围需要权衡。

这些研究提供设计动机，不证明同样机制在 Context Keeper、多宿主或其他模型上有效；不同模型间的表现差异也不能单独证明某种文件组织导致提升。本文的优先级、实验设计与实现建议是针对本项目的推导。

## 3. 现有能力与真正需要补齐的部分

| --- | --- | --- |
| 分层记忆 | 日志、主题摘要、经验、索引、原始会话检索 | 各层能否在真实任务中协同纠错 |

| 成本控制 | 读取预算、快速路径、压缩提醒 | 完整任务周期内的收益是否超过维护成本 |

`search --for-write` 的职责是写前经验对照与去重。它不搜日志是已知范围，不能直接判为缺陷，更不能单独解释续接失败。应检查从检索到来源展开再到判断的完整过程。

## 4. 建议方案

### 4.1 验证并改善反证可达性

**问题。** 旧经验可能先占满候选；后续日志未扫描，或已被索引链接而不再单独展示。即使输出“覆盖受限”，Agent 仍可能接受旧结论。当前代码支持此风险判断，但尚未证明具体任务必然失败。

**如何解决。** 先构造旧摘要与后续纠正并存的样本，追踪反证在哪一步消失：未进入扫描、被去重、未被展开，还是读到了却误解。只有证据表明需要改动，才在现有检索/读取路径中作最小修正。

候选做法包括：在明确矛盾、同类失败或将采用关键旧结论时，为相关新增证据保留有限读取预算；对已链接来源提示展开义务；保留覆盖范围和停止条件。不要在所有普通任务中自动扫描全部日志。具体采用哪种做法由实验决定，不能同时叠加后再猜测哪项有效。

**依据。** C2、C3，以及外部研究的回查纠错思路。外部研究不规定本项目的候选配额和算法。

**验收。** 能找到直接相关反证，指出来源并正确收窄旧判断；证据不足时保留不确定性。旧结论仍正确的样本不能被错误降级，普通任务不能被迫进行全库查询。

### 4.2 按证据内容纠错

**问题。** 有链接不代表结论可靠。原始会话中也可能只是 Agent 说“测试通过”，而没有工具结果；两个宿主转述同一次运行不构成两次独立验证。

**如何解决。** 沿来源区分用户要求、工具观察、当时判断和后续推断。验证过去发生了什么时核对当时记录；判断现在是否适用时核对当前代码、版本或环境。证据不足时标注未知，不把新时间戳自动当作更强证据。

复用现有字段和日志正文，优先改善读取与判断指令，不先增加证据数据库或强制字段体系。

**依据。** C3、C4、C5。原始会话可帮助核查，但并非每一句都是真值。

**验收。** 能识别摘要与实际结果不一致、重复转述、不同版本不可比、局部成功被扩大等情形；纠正必须说明适用范围和直接依据。

### 4.3 检查经验规则是否造成信息遗漏

**问题。** 不同问题重复验证有助于防止过度泛化，但如果 Agent 将其理解为“任何有价值发现都必须等第二次才保存”，单次证据充分的局部事实可能长期埋在日志里。

**如何解决。** 先观察现有规则实际是否导致遗漏。若确实出现，澄清三类内容：局部事实可及时保存为当前认识；尚未验证的方法保留为待验证候选；跨场景推荐的方法需要匹配其适用范围的验证。事实保存、可检索和可推荐应分别判断。

现有主题记忆已能保存局部事实，应优先使用它。只有现有表达持续导致误解时，才调整 Skill 或 references；不预先放宽“已验证”状态标准。

**依据。** C4、C5。外部研究关于指导方式的发现提供审查理由，但不能推出“规则越少越好”。

**验收。** 单次确定事实不遗漏；未经验证的猜测不成为执行建议；一次测试不被描述为跨场景有效；同一事实重复输入不产生重复经验。

### 4.4 以完整任务收益衡量记忆

**问题。** 文件格式合规、检索命中、保存成功，都不足以证明记忆改善了任务。整理还可能节省读取却增加更多生成成本。

**如何解决。** 统计从读取到执行再到保存的完整周期：任务是否完成、错误是否复发、是否错误采用或错误推翻经验、输入输出 Token、墙钟耗时和维护动作。一次整理的成本与后续复用收益分别记录；只有出现多次真实复用，才讨论摊销收益。

成本数据缺失时写缺失，不从文件字节数推算精确 Token，不将价格未知时的 Token 差异直接写成费用差异。

**依据。** C3 的真实行为验收与外部研究对整理成本的讨论。

**验收。** 能比较相同条件下的正确性与成本，报告全部失败和变异；不以一次成功宣称长期可靠，也不单独以更少 Token 判定改进。

### 4.5 将整理限定到有证据需要的主题

**问题。** 即使反证已找到，当前摘要、经验与索引也可能不同步，导致下一次仍沿用旧判断。

**如何解决。** 仅在前述实验确认有持续需求后，试验在既有自然收尾节点检查一个相关主题：核对来源、修当前认识、更新状态和索引、追加纠正记录。保持原日志不变；来源不足就保留待验证。每次整理有明确输入、读取预算、输出与停止条件。

**依据。** C1、C4、C5 已有大部分操作能力。新增价值应来自正确执行和触发，不来自新增名词或目录。

**验收。** 下一会话可采用修正后的适用范围；重复整理相同证据没有内容增量；无关主题无变化，历史记录完整，整理成本可测。

## 6. 实验设计

### 6.1 样本与评分维度

样本须覆盖摘要滞后、中段反证、有效旧结论、版本/输入不可比、同run重复转述、摘要与工具结果冲突，以及重复保存、无历史信号的新任务。固定夹具覆盖stale、middle、linked、saturated、valid、version、duplicate、claim；初始样本中答案提示较强，不能追认为盲测。保存幂等和自然触发没有被只读哈希检查替代，仍需独立验收。

### 6.2 对照条件

A：当前检索与原始记忆，作为基线。

B：保留原始记忆，确保相关证据进入可读取范围，检查可达性的影响。该条件用于诊断；人为提供证据的成功不能算自动检索通过。

C：使用已经正确修订的记忆，检查错误内容本身的影响。人工修订的成功不能算自动整理通过。

需要量化记忆总体价值时，可增加无记忆基线；本轮定位优先使用 A/B/C，避免扩大实验规模却无法定位原因。

固定实际模型信息、宿主版本、任务提示、工作区快照、工具权限和预算。每个条件使用隔离的新会话和记录副本，防止前一轮输出泄漏。预先约定重复次数，保存全部结果；小样本只报告观察，不推算长期可靠率。

### 6.3 判定与下一步

- A 失败、B 成功：优先调查证据可达性；仍需区分额外上下文、提示变化等影响。
- B 失败、C 成功：优先调查证据解释和冲突处理，不能直接断定需要后台整理。
- C 仍失败：调查任务执行或记忆采用能力，不继续堆叠记忆结构。
- A 已稳定通过：保留当前设计，核算成本，再决定是否有必要优化。

正确性底线包括：不错误推翻有效经验，不越过适用范围，不把猜测升格为验证，不改写历史。与基线比较成本时，须包含新增整理成本。预算上限和可接受波动在实验前确定。已记录的各阶段成本不能跨任务、跨预算直接相减，不预设百分比收益。

## 7. 不借鉴或暂缓的做法

| 做法 | 当前决定 | 原因 | 何时重新评估 |
| --- | --- | --- | --- |
| 常驻后台 dreaming、定时全量蒸馏 | 暂缓 | 当前架构明确保持轻量；尚未证明自然节点整理不足，后台还增加成本和并发写入问题 | 主题级整理有稳定收益，且延迟整理确实影响任务 |
| 新建通用 Wiki 或知识图谱层 | 暂缓 | 已有主题文件与索引；多一层会增加同步与事实漂移负担 | 大量真实跨主题问题证明现有结构无法高效支持 |
| 每个任务都扫描全部记忆 | 不采用为默认 | 破坏按需读取边界，成本随历史增长 | 只在明确调查中允许有预算地扩大范围 |
| 把所有记忆注入每个新会话 | 不采用 | 无关内容占上下文，错误结论被反复传播 | 仅评估小型入口与任务相关定位，不全量注入 |
| 无差别记录工具输出和可即时读取状态 | 不采用为默认 | 重复、易过时；维护成本可能超过价值 | 审计或故障复现确实需要时，保留必要证据 |
| 删除全部约束、完全交给模型自由判断 | 不采用 | 多模型行为不一致；授权、历史保护和事实边界仍需明确 | 可定点精简经对照证明冗余的指导 |
| 仅记录失败，或只记录成功 | 不采用 | 会丢失另一类可用证据，不能服务完整学习过程 | 按任务价值选择内容，不按成败一刀切 |
| 多 Agent 同时改同一主题记忆 | 不采用为默认 | 容易覆盖更新；当前没有必要为此引入复杂并发存储 | 如确有并行需求，先按文件明确单一写入者，汇总由一处完成 |
| 整理时覆写原始日志 | 不采用 | 会破坏判断演变与纠错依据 | 当前认识可更新；历史错误通过追加更正处理 |
| 直接照搬文章的模型配置、规模或收益数字 | 不采用 | 本项目的数据、任务、宿主与成本条件不同 | 只用本项目实测结果决定投入 |
| 为本次提案新增 review-evidence 专用命令、数据库或复杂台账 | 暂缓 | 现有路径已可承担大部分操作；先确认缺口再增加机制 | 最小修正经验证仍不足时提出独立设计 |

这些决定不否定外部研究的价值，而是限定它在当前产品规模和证据条件下的适用范围。

| T6 | 多批CLI新会话与成本已记录；旧新指引各2/2发现事实但新两次输出超通常80行，无净收益证明 |
| T7 | 暂不实施，没有证据支持后台或主题整理新机制 |
| T8 | 文档归并、纯评估支持与干净环境复验已完成；不把文字精简等同模型行为等效 |

当前后续顺序：先按任务需要收紧宽关键词输出及证据定位，再决定真实项目、独立模型/宿主验证范围；不为补齐清单持续增加同一合成样本。提交与发布分别确认，不因本地通过自动执行。发布包仅包含声明资产，不包含实验输出、认证引用或本机档案。

## 9. 已采纳的T4最小合同

首批选择F3文件内截断可见性，是因为F1候选满额已有覆盖提示、F2来源去重已有链接定位，而F3没有说明同文件后续匹配被省略。先补输出解释，不重排候选、不扩大默认读取量，也不声称恢复了全部反证召回。

- 内部帮助函数返回有限片段与是否仍有匹配，保留旧`_file_hits`列表接口。对正limit找到第limit+1个匹配即可确认截断，不为计算总数再读一遍文件；原文件读取仍非字节硬上限。
- 普通search只在实际展示经验正文、索引回退或历史文件片段有省略时，在对应候选下提示“文件内匹配展示受限”。索引回退按实际索引匹配判断，不把正文截断标到索引上。
- 提示每候选最多一行，不占候选位；5候选、经验3条和每文件3命中的默认值不变。不把额外匹配等同于反证。
- `--for-write`展示字段摘要，不加匹配行提示；resume、history-search、当前主题、时间线和单行字符裁剪不在这次提示覆盖范围。非正limit保留原切片语义，不借此新增参数校验。
- 零命中、恰好上限、完整展示不误报；待验证经验前缀及已替代过滤不变。每文件截断提示与全局候选/扫描限制独立。

关键回归覆盖middle默认3条/显式10条、恰好3条/零命中、多个候选提示归属、待验证状态、索引回退、for-write/resume边界及输入只读。实现、测试和本地包各自验收，不以结构或哈希通过替代语义判断。

## 10. 未采纳改法的重新进入条件

**F2来源去重。** 来源已链接不代表正文已读，但也不代表证据不可达。先在自然任务中观察是否展开1～2份相关来源；预算内能找到反证就保留去重。若独立重现未展开，再单独试验“链接只作定位、正文未展示”的提醒，不递归读外部链接，不把提醒有效当作预设结论。

**F1候选排序。** 只有真实新会话反复出现关键来源被压制、且来源展开不能解决，才在同总预算下比较配额/顺序。必须计入有效旧经验被挤出的代价，并覆盖无相关新日志、旧结论有效、版本不同和宽词噪声；不能只看反证召回。当前CLI缺口仍在，但绕行成功或失败均未证明具体算法改法必要。

**预算与定位。** 用于定位的索引不挤占1～2份事实依据，引用摘要仍须核对；通常80行是单次展示，不是会话累计硬限。出现截断、追加或冲突时先在已选来源按问题关键词定位，再读邻近上下文。固定head/tail不能排除中段纠正；命令帮助开销另报，实验10命令上限不是产品合同。不强制每次续接额外search或全库扫描。

**整理与验证。** 保留日志只追加、当前认识可修订、范围内反证降级及用户授权边界。任何进一步规则、输出或读取方式变更都须独立冻结验证；当前报告没有生产恢复、长期成功率、跨宿主等效或提示净收益证据。

## 11. 用户流程与异常处理

1. 用户提出续接或历史查询，按现有Skill触发边界定位当前状态和有限候选；普通新需求不额外检索。
2. Agent区分当前摘要、历史定位和事实来源。对最相关1～2份来源核查输入、版本、run ID、执行状态和直接结果。
3. 命中片段被截断、存在追加或结论冲突时，在所选文件内定位关键词及邻近上下文。覆盖不足或预算耗尽时明确尚未读到什么，不猜测成功，不自动扩大到全库。
4. 有范围内反证时收窄当前认识；不同条件分别保留，同次运行多处转述不增加独立验证数。只读查询不改记录；需要保存时沿用既有保存路由、授权及历史只追加约束。
5. 对外答复分别说明已验证范围、未解决项和来源。路径可定位、CLI退出0及模型自述都不是事实已读取或业务已完成的充分证据。

环境启动失败与产品失败分开处理；认证写入被拒时报告阻塞，不复制凭据或放宽真实配置写权限来换取通过。检索零命中、文件匹配截断和未扫描来源分别说明。

## 12. 验收标准与证据边界

| 需求 | 可观察的验收标准 | 验证方式与当前边界 |
| --- | --- | --- |

| 读取预算 | 索引与事实来源分开；通常80行按单次展示；不把首尾窗口当全文核验 | references语义核对及受控新会话；旧新各2次均发现事实，新两次展示106行，尚无净效率提升证据 |
