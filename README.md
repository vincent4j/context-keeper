<a id="为什么需要-context-keeper"></a>

## 💡 为什么需要 Context Keeper？

你用 AI 写代码时，是不是也遇到过这些问题？

- 🔄 **昨天做到一半，今天想接着做，却又得从头交代？** → 昨天需求讲清了、方案定好了，任务还没做完。今天回来继续，AI 却不知道昨天做到了哪、接下来该做什么，又得你重新讲一遍。
- 🔍 **明明记得这件事以前做过，却想不起来当时是怎么做的？** → 用了什么方法、为什么这么选、最后结果怎么样，都记不清了。想接着用，还得自己翻聊天、找记录，重新捋一遍。
- 🧠 **同一个错误，明明纠正过，AI 下次还是照犯？** → 当时回答“记住了”，换个任务就忘了。你反复强调同一件事，上次踩过的坑没有变成下次能用的经验。

**难道每次都得你来交接进度、翻历史、提醒它别再犯错？**

Context Keeper 帮 AI 保存项目进度、找回历史事实，更让它在使用中**持续自我进化**：自动沉淀新的纠正和验证结果，修正过时经验，让这次学到的东西改变下一次的做法。

📦 **把下面这段话复制给你正在使用的本机 Agent：**

```text
请克隆 https://github.com/vincent4j/context-keeper，运行仓库中的 scripts/install.py --all 安装 Context Keeper。完成后告诉我结果。
```

重新打开客户端后，确认它已识别这个 Skill。

### ✅ 在你用之前，你可能想知道

| | |
|---|---|
| ⚡ **会多花 Token 吗？** | 普通新需求不查历史；需要时只读少量相关记录，同一问题不反复查。不全量加载聊天，也不承诺零 Token 成本。 |
| 📝 **需要自己维护吗？** | 保存记录、整理经验由 AI 执行。你不需要手写日志、整理文件或维护一套知识库。 |
| 🔎 **会不会编造“以前的经验”？** | 历史结论必须有记录支撑。与你记得的不一致时展示原文，没找到就说明没找到；推断不能冒充事实。 |
| 🤖 **我的 Agent 能用吗？** | 提供 Codex、Claude Code、Cursor、WorkBuddy、Hermes、OpenCode 和 OpenClaw 的原生 Skill 目录安装。只有 Codex 和 Claude Code 目前写入自动入口；其余五个等待真实运行时验收后再启用自动规则。 |

## 🎯 能帮你做什么？

| 你遇到的问题 | Context Keeper 怎么处理 | 你得到什么 |
|---|---|---|
| 昨天没做完，今天接不上 | 保存需求、决定、实施进度和未完成事项；续接时恢复相关记录 | 不用重新整理交接材料，接着已有进度往下做 |
| 记得以前做过，却忘了当时怎么做 | 从当前问题提取线索，先查项目记录，必要时定位原始会话 | 当时的做法、结果和出处，判断这次是否适用 |
| 同一个错误反复犯，新方法和新结论留不下来 | **自我进化：**自动沉淀新经验，根据新证据修正旧经验 | 少走已知的弯路，有依据地采用更合适的方法 |

保存和查找让项目接得上；项目继续推进，又会带来新的纠正、方法和验证结果。这些新发现也会留下来，成为下一次工作的依据。

<a id="自我进化"></a>

### 🧠 自我进化如何发生？

**从这次工作中沉淀经验，再用新证据改进后续做法。** Context Keeper 在下面三种情况下自动更新经验，不需要你再发“总结一下”“记住这次教训”，也不需要你手工维护经验清单。

| 遇到什么 | 自动沉淀什么 | 下一次有什么不同 |
|---|---|---|
| **你指出了明确错误** | 纠正、事实依据和适用范围 | 遇到同类问题时，找回纠正，避免沿用错误做法 |
| **失败后换了方法，验证有效** | 新方法、有效条件和验证结果 | 有经过验证的方法可选，减少从头试错 |
| **新证据推翻了旧经验** | 修正适用范围，或将旧经验标为已替代 | 后续检索采用当前适用的经验，不继续推荐过时结论 |

**自动沉淀 → 按需检索 → 影响行动 → 根据新证据继续更新。**

随着项目推进，这个过程会持续积累新的经验，并修正不再适用的做法。**你正常推进任务，AI 按规则自动沉淀、检索和更新，让自我进化融入日常使用。** 积累新经验不需要反复升级 Skill，也不需要训练模型；没有验证结果的想法不会被包装成有效方法。

> ✨ **每次进化，你都能感知。** 沉淀后告诉你记下了什么；实际复用后告诉你改变了哪个判断或动作。找到经验、采用经验、验证有效，分别说明。

<a id="快速上手"></a>

## 🚀 快速上手

日常操作只有保存、继续、查找三个入口，自我进化随任务处理按上述规则进行，无需单独开启。

在支持 Skill 斜杠选择的对话框里，输入 `/`，再输入 `context` 筛选，选择 **`/context-keeper`** 并发送。

首次调用会先检查并补齐当前 Agent 的自动入口；配置完成后，AI 会给出三个选项：

```text
你想做什么？

1. 保存 —— 记下本次需求、进度和未完成事项，方便下次继续。
2. 继续 —— 找回上次进度，接着做没完成的任务。
3. 查找 —— 查找当前问题的历史记录和相关经验。

回复 1、2 或 3 即可。
```

历史检索也有自动入口：提到“以前、上次”，或当前处理失败、准备重试而又缺少依据时，Agent 按需检查相关记录。普通任务不额外跑一遍历史搜索。

### Agent 支持范围

| Agent | 安装目录 | 自动入口 | 当前验证 |
|---|---|---|---|
| Codex | `.agents/skills`、`.codex/skills` | 支持 | 已做运行时验收 |
| Claude Code | `.claude/skills` | 支持 | 已做部分运行时验收 |
| Cursor | `.cursor/skills` | 未写入 | 安装器已覆盖，待客户端验收 |
| WorkBuddy | `.workbuddy/skills` | 未写入 | 安装器已覆盖，待客户端验收 |
| Hermes | `.hermes/skills`（用户级）或 `.agents/skills`（项目级） | 未写入 | 安装器已覆盖，待客户端验收 |
| OpenCode | `.config/opencode/skills`（用户级）或 `.opencode/skills`（项目级） | 未写入 | 安装器已覆盖，待客户端验收 |
| OpenClaw | `.agents/skills` | 未写入 | 安装器已覆盖，待客户端验收 |

`--all` 让上述全部目录复用同一份源码。共享目录只处理一次；发现同名配置已指向其他位置时，安装器会停止，不会替换它。

## 📁 项目里会新增什么？

第一次保存前，AI 会先调用 `init` 询问你准备在哪里创建记录库：默认建议 `docs/context-keeper/`，但不会自动创建。你可以同意默认位置（AI 重跑时加 `--approved`），也可以直接告诉 AI 你想用的目录（例如 `notes/history/`）。记录库结构如下：

```text
你的项目/
└── docs/
    └── context-keeper/
        ├── memory-keeper.md          # 项目进度、未完成事项和记录入口
        ├── plans/                   # 用户需求与实施计划
        │   └── 2026-09-17-登录功能.md
        ├── worklogs/                # 实际工作、结果与反馈
        │   └── 2026-09-17-登录功能.md
        └── evolution/               # 自我进化积累的经验
            ├── index.md             # 经验索引，方便按需查找
            └── 登录排错经验.md       # 事实依据、适用范围与建议做法
```

| 目录 / 文件 | 作用 |
|---|---|
| `docs/context-keeper/` | 集中存放这个项目的记忆与经验，方便后续继续工作和查找历史。 |
| `memory-keeper.md` | 项目记忆的总入口：记录当前进度、未完成事项，并链接到相关计划、日志和经验。 |
| `plans/` | 保存你提出的需求、确认的范围，以及围绕这些需求形成的实施计划，方便追溯“当时要做什么、准备怎么做”。 |
| `worklogs/` | 保存实际做了什么、结果如何、遇到哪些问题、你给了什么反馈，以及还有什么没完成。 |
| `evolution/` | 保存自我进化沉淀的经验，包括纠正、验证有效的方法和被新证据修正的旧结论，供后续任务按需采用。 |
| `evolution/index.md` | 经验的查找入口：通过主题、触发条件和适用范围定位相关经验，避免每次读完整个经验库。 |

文件名仅为示例，具体记录按实际任务生成。**这些文件由 AI 维护，你随时可以打开阅读。** 需求和工作日志使用“日期＋中文主题”命名，经验按主题拆分，避免越积越多都堆在一个文件里。

AI 调用 init 后会先告知建议位置；想换位置，直接告诉 AI 即可。AI 不会自动创建记录库，必须等你确认。

<a id="设计理念"></a>

## 🧭 设计理念

**让项目延续下去，让历史有据可查，让 AI 在使用中持续自我进化。**

一次开发会产生需求、决定、尝试、结果和纠正。它们如果只留在聊天里，换个会话就得重新找、重新讲。Context Keeper 把这些内容保存为可读的项目记录，再按当前任务提取需要的部分。

- **先找事实，再下结论。** 原文、摘要和推断分开，不能为了接上话而编造过去。
- **先定位，再展开。** 只读取与当前问题相关的少量内容，把上下文留给正在做的事。
- **历史保留，经验更新。** 跨会话新增需求和工作记录；经验被修正时保留新旧证据，不用今天的结论覆盖昨天的事实。
- **在使用中自我进化。** 有明确纠正或新的验证证据时自动沉淀、修正经验，让后续做法持续改进；不需要你手工整理，也不需要每次升级 Skill 或训练模型。
- **保持轻量。** 使用 Markdown，默认按项目隔离，不引入复杂 hooks、向量数据库或后台服务。
