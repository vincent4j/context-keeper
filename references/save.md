# 保存本次上下文

## 1. 初始化与会话边界

无项目聊天仅在用户明确要求保存时进入本流程；纠正、新结果或临时工作目录均不触发自动保存、`status`、`init`、建库预览或建库询问（详见 SKILL.md 无项目聊天边界）。没有已获授权记录库且用户未要求保存时直接交付，不因阶段结果、纠正或失败自动建库或询问；已有授权记录库且无用户禁止保存/改文件的限制时，按 SKILL.md 的触发与跳过规则判断新事实。同一会话不重复提出已悬置或被拒绝的保存询问。

命令返回“需要迁移”（退出码 3）时停止，按 [迁移说明](migrate.md) 预览并取得用户确认；不得绕过门禁读写旧记录。

首次保存前必须先初始化并取得用户确认记录库位置：

```bash
# 询问模式（默认）：打印建议路径，不创建任何目录；rc=5 需要用户确认
python3 <skill-dir>/scripts/context_keeper_probe.py init --root <repo>
# 用户同意默认位置后加 --approved；或用 --store-dir 指到自定义路径（同样需 --approved）
python3 <skill-dir>/scripts/context_keeper_probe.py init --root <repo> --approved
python3 <skill-dir>/scripts/context_keeper_probe.py status --root <repo>
```

init 返回值：rc=0（已创建或已就绪）/ rc=2（拒绝：迁移需 `--migrate`、配置无效、目标冲突）/ rc=5（需要用户确认，先展示建议位置再重跑）。脚本按 `<repo>/docs/context-keeper/`、`<repo>/context-keeper/` 自动发现已有记录库；不在候选位置或歧义时用 `--store-dir <path>` 显式指定。`--store-dir` 指到候选位置之外才写 `context-keeper.json`。改记录位置用 `init --store-dir <path> --migrate --approved`，不能直接创建第二套记录；迁移若会改变历史文件中外部证据链接的指向会停止，不为迁移改写旧会话记录。

为当前会话使用稳定的 `session-id`（优先平台当前会话 ID，不复制旧记录的 ID）。第一次写入前运行 `record-path` 或 `record-guard` 建立旧计划和日志的内容指纹（保存在用户缓存，绑定仓库实路径、记录库实路径和会话 ID）；缺少基线不能宣称历史保护已验证。脚本直接创建带会话标识的文件：

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py record-path \
  --root <repo> --kind plan --title '<中文主题>' --session-id '<session-id>'
python3 <skill-dir>/scripts/context_keeper_probe.py record-path \
  --root <repo> --kind worklog --title '<中文主题>' --session-id '<session-id>'
```

更新本会话 plan 或向本会话 worklog 追加之前必须运行（同会话快速路径可复用已验证结果）：

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py record-guard \
  --root <repo> --path <record> --session-id '<session-id>'
```

非 0 时停止本次写入并说明原因；若因跨会话或迁移历史拒绝，运行 `record-path` 创建当前会话新记录并链接旧文件。guard 通过不授予覆盖日志的权限。

## 2. Plan 内容

只有存在需要保留的明确需求或实施方案时才创建，不因任务类型机械创建；已有权威文档时只记录本轮变化并链接来源。Plan 使用以下短章节，暂无的内容写“无”，不为补齐格式编造需求：

```markdown
## 用户需求
用户原话或忠实总结，注明来源。
## 范围
已确认要做和不做的内容。
## 实施计划
围绕上述需求的步骤。
## 验证方式
可观察的验收结果。
## 待确认
无，或尚未确认的问题。
```

用户原话、忠实转述和 Agent 判断保持可区分；校验只能证明字段存在，是否忠于用户事实仍需逐项核对当前对话。同一会话、同一主题可以更新计划；能独立实施或需要单独检索的主题分别建 plan；跨会话必须新增记录。

## 3. Worklog 内容

工作日志只追加，包括同一会话内。记录当时的目标、实际操作与方法、观察结果、当时判断、后续动作和证据；失败尝试、错误方案和当时错误结论均保留。操作事实与当时判断分开，不把计划写成已完成，不把工具成功写成用户认可。

每次自然节点只整理尚未成功保存的新事实。同会话同主题在原文件末尾新增带时间段落；跨会话创建新日志并链接旧记录。已有正文、反馈和旧摘要不覆盖、不删除；纠正事实或文字也另追加说明，写清新证据及原记录定位。相同操作再次发生且输入、结果或意义改变，仍属于新事实。

### 事实日志与当前摘要

新日志记录真实过程即可，不要求每次保存或追加都生成独立快速摘要、盲点和经验反馈。已有旧格式章节保持原样，仍可作为历史线索读取，不为新规则补写旧日志。

同会话同主题在日志末尾追加带实际时间的记录，例如：

```markdown
## 追加记录 YYYY-MM-DD HH:mm:ss +08:00

- **目标与背景：** 本次工作节点。
- **操作与方法：** 当时实际采取的步骤。
- **观察与当时判断：** 区分实际结果、推断和未验证项。
- **后续与证据：** 下一步、恢复条件和来源链接。
```

时间使用实际时区，示例不是强制时区。日志只追加通过指令约束，不建立追加段 ID、写入口、锁、逐次指纹或回执机制。发现错误另追加说明；当前进度和摘要更新到 memory-keeper，不回改旧摘要。

本轮用户反馈由 Agent 依据当前对话说明，最多保留必要的新认知；没有新增认知时不编造。经验只有实际影响本轮判断或动作才称为采用，得到本轮结果证据后才称为验证有效。不把日志旧反馈当成本轮反馈重复发送。

## 4. Memory 与未完成事项

`memory-keeper.md` 可以更新，保存当前进度、未完成事项、项目要求和对应主题摘要，保留来源日志链接。它维护当前认识，不能借更新摘要改写日志历史。先找同主题再更新，只改发生变化的部分；已完成或取消的事项不继续占据当前待办，不把普通进度都写成编号经验。当前主题摘要放在已有的 `## 主题摘要（按类型）` 下，同主题优先更新同一条简短内容，例如：

```markdown
- **接口修复：** 已改用方案 B，尚待端到端验证；下一步：获得权限后验证；来源：[日志](worklogs/YYYY-MM-DD-接口修复.md)。
```

项目要求和约定可放在 `## 项目要求`、`## 项目约定` 等明确小节；不要把当前要求仅埋在历史时间线。相关主题先筛选后限量输出，较长条目显示有限内容并保留简短来源/下一步入口，需要时再展开原文。

必要验证、未完成部分和来源都应可定位；详细过程仍在日志。主题摘要只反映当前认识，不将旧失败记录从时间线或日志中抹去。

时间线按以下结构加入本次 plan/worklog 的链接（最新在前），只链接实际存在的文件，类型使用本轮实际类型：

```markdown
## YYYY-MM-DD - 中文主题 `feature`
- **任务：** 本轮任务。
- **关键经验：** 有证据的结论；没有则省略。
- **详见：** [计划](plans/YYYY-MM-DD-中文主题.md)、[日志](worklogs/YYYY-MM-DD-中文主题.md)
```

时间线超过 15 条时，先压缩最旧条目再写入，控制后续每次保存的读取成本：

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py compact --root <repo>
# 预览保留/归档条数和体积变化，用户确认后加 --approved 执行
python3 <skill-dir>/scripts/context_keeper_probe.py compact --root <repo> --approved
```

归档条目合并为单行（日期、类型、主题、任务一句和记录链接），放在时间线分隔线之后的“时间线归档”章节，不再进入续接候选，但链接保留。当前 `search` 的时间线分支不直接覆盖归档区，有限回退原日志也不保证完整召回；不得宣称归档已被完整检索。历史文件不被改写。

保存收尾时 `save-report` 会检查 memory-keeper 体积并按阶梯提醒：20KB 起每增长 10KB 一级（20/30/40/50…KB）。提醒会附带编号选择，原样转达给用户，用户回复 1 就运行 `compact --approved`（该回复即为确认），回复 2 就运行 `compact --snooze` 记录当前级别，之后不再重复询问，增长到下一阈值才再提醒。压缩后从压缩后的体积重新起算。

未完成事项使用以下格式，便于续接时按当前任务筛选：

```markdown
- <事项>；状态：<未开始/进行中/阻断/已完成/已取消>；触发：<什么时候需要处理>；完成：<关闭条件>；证据：<验证位置>。
```

局部完成不能关闭更大的待交付事项；索引可以更新，但不能借更新索引改写历史文件的含义。保留 `evolution/index.md` 入口。

## 5. Evolution

进入经验前先回答：下次什么场景会用到、它改变什么判断或动作、依据是什么及适用范围。回答不清楚时留日志或当前状态，不建立编号经验；一次成功不自动形成长期规则。用户要求与技术验证结果分开，未验证判断明确标为待验证。

同一方法在不同问题或业务入口的实际修复中重复验证，且上述问题已有答案时，本轮自然收尾应完成经验整理，不等待显式“保存经验”请求。关联各次验证日志，先查同主题：有则保留编号、补证据/修范围；没有覆盖该认识的主题才新增一条并更新索引与当前记忆。只更新日志或主题摘要不代表经验整理完成。一次修复内的多个用例、原样重复运行、偏好或未经验证的推断不满足这个触发条件；不能按次数机械新增，仍需核对方法与适用条件。局部验证只支持相应局部范围。

先查 evolution/index.md 和同主题文件。按主题、场景和建议动作判断是否重复：已有同主题只补证据或修订适用范围；独立新经验才新建文件和编号并补索引。正文保持简洁，不按日期追加流水；详细操作、验证和认识演变留日志。偏好和项目要求更新 memory-keeper 对应主题，不机械生成经验。

经验沿用以下结构，最多 2000 字符：

```markdown
# <经验主题>

- **编号：** CK-<唯一编号>
- **状态：** 待验证|已验证|已替代
- **触发条件：** <什么情况下检查>
- **已知事实：** <区分用户要求、运行结果和待验证推断>
- **证据位置：** <原始记录或验证证据链接>
- **建议动作：** <下次具体做什么>
- **适用范围：** <项目、版本、输入和边界>
```

结论被推翻时保留旧事实与证据，标为已替代，增加指向当前有效经验的替代链接，索引同步更新，不能循环或形成替代链。没有新经验时正常记录进度，不要求创建经验文件。

项目经验默认留项目。只有用户明确确认跨项目复用后，才运行 promote-evolution --approved；不因整理自行扩大适用范围。

## 6. 校验与交付

### 同会话快速路径

同一会话、同一仓库和同一主题中，如果 bridge、`status` 和目标文件的 `record-guard` 已成功，且仓库、分支、记录位置、会话 ID 与外部文件状态没有变化，则连续纠正不重复这些检查。只追加已存在且已索引的日志或更新主题记忆时，写完运行一次 `save-report`；新建记录、改索引/链接/结构时才补 `coverage`。多个独立 guard 可并行，必要的 `coverage` 与 `save-report` 可同批并行。快速路径只减少重复启动和读取，不降低会话边界、历史指纹、迁移门禁或保存校验；内容准备好后的本地收尾目标不超过 5 秒，超时须指出慢项。

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py coverage --root <repo>
python3 <skill-dir>/scripts/context_keeper_probe.py save-report \
  --root <repo> --worklog <worklog> --session-id '<session-id>'
```

`coverage` 默认只输出计数，需要定位时再加 `--details`。missing_summary 仅提示缺少历史快照摘要，不是新日志必填失败项。历史遗留缺口只报告，不批量修补；本次新增的缺项、重复经验、缺索引和断链必须修复，不能用“历史遗留”跳过本轮问题。`save-report` 非 0 时只修复本次未保存内容、允许更新的主题记忆或缺失链接；已保存日志不回改。无法在保留历史的条件下完成现有校验时，保留实际内容，说明保存/校验各自完成到哪里，不能宣称完整保存通过，也不绕过门禁。保存检查会比较本会话开始记录的旧文件指纹，旧记录修改或删除都会阻断交付；该检查不是文件系统访问控制。

`save-report` 只报告实际检查的会话归属、跨会话历史基线、当前主题条数、索引和当前主题直接链接的经验字段、索引和来源链接；没有当前主题时明确未验证当前状态。它不再强制日志摘要或反馈，不证明本轮事实语义与实际修改集合。Agent 读回本轮写入，核对当前主题和待办是否更新，相关经验是否保留依据；本轮增量及复用结果由 Agent 简短说明，旧反馈不复播。

最终仅说明本次真实变化和必要来源。用户已经授权提交或推送时按授权执行，只处理本轮相关文件。
