# 继续上次进度

先运行续接命令，返回“需要迁移”时立即停止，不绕过门禁读旧目录：

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py resume \
  --root <repo> --query '<当前任务关键词>'
```

## 当前状态优先

普通多关键词查询可用空格、制表符或换行分隔，按任一词命中召回，并沿用输出条数限制。例如 `--query '订单 编号 空字符串 首尾空格 验收'`。已有显式正则（如 `订单|客户`、`订单.*验收`、含分组/转义的表达式）保留正则语义，表达式内部空格不拆词。history-search 仍按原正则查询，不受此调整影响。

脚本优先展示与关键词相关的 memory-keeper 当前主题、项目要求和未完成事项，再展示有限历史线索。主题先筛选再取最多 5 条，保留同条目的下一步与来源续行；较长条目只展示有限内容并提示按来源展开。来源缺失或冲突时说明边界，不能让旧日志首次摘要替代当前状态。

- 继续工作：先当前进度、约束和待办，再按需看经验。
- 处理类似问题：先相关有效经验，核对适用范围和当前条件。
- 查当时发生什么：定位对应日志，保留当时判断与后来认识的区别。
- 当前上下文足够：不额外读取历史。

历史工作摘要仍取日志首次快照，明确标为历史，不是最新进度。旧日志没有摘要时有限提取并标明不完整；不为续接批量改写旧日志，也不要求每个追加段独立摘要。

如果没有命中当前主题，不能只用历史摘要认定最新进度；在同一记录库内按已有来源有限读回当前记忆或相关日志核对，仍不扩大成全量历史扫描。

默认最多 3 份历史短摘要、5 条相关待办及最多 5 条经验/时间线候选。只展开最相关的 1～2 份来源，每次通常不超过 80 行。普通新需求不检索，同一问题本轮不重复，除非出现新证据或路线变化。

当前摘要也可能过时。涉及文件、代码、版本或环境时定点核验；待验证经验明示，已替代经验不作为当前建议。历史下一步不构成当前执行授权。缺依据时如实说明，必要时按检索说明限量查原始会话。
