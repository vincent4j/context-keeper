# 继续上次进度

先运行续接命令，返回“需要迁移”时立即停止，不绕过门禁读旧目录：

```bash
python3 <skill-dir>/scripts/context_keeper_probe.py resume \
  --root <repo> --query '<当前任务关键词>'
```

## 当前状态优先

普通多关键词查询可用空格、制表符或换行分隔，按任一词命中召回，并沿用输出条数限制。例如 `--query '订单 编号 空字符串 首尾空格 验收'`。已有显式正则（如 `订单|客户`、`订单.*验收`、含分组/转义的表达式）保留正则语义，表达式内部空格不拆词。history-search 仍按原正则查询，不受此调整影响。

脚本按读取合同分层输出，层级是读取深度，不是三份存储：L0 定位（主题标题、待办行、时间线一行候选与 `evolution/index.md` 入口）→ L1 当前认识（当前主题条目的有限展开，含下一步与来源续行）→ L2 事实依据（日志、计划与经验正文）。默认只到 L0/L1；进入 L2 需要显式意图或来源不足。

默认优先展示与关键词相关的 memory-keeper 当前主题、项目要求和未完成事项，主题先筛选再取最多 5 条，保留同条目的下一步与来源续行；较长条目只展示有限内容并提示按来源展开。当前主题自带的来源链接就是必要的 L2 定位，默认不再附无关近期日志。来源缺失或冲突时说明边界，不能让旧日志首次摘要替代当前状态。

- 继续工作：先当前进度、约束和待办，再按需看经验。
- 处理类似问题：先相关有效经验，核对适用范围和当前条件。
- 查当时发生什么：定位对应日志，保留当时判断与后来认识的区别。
- 当前上下文足够：不额外读取历史。

历史工作摘要属于 L2，默认不自动展开；仅在显式 `--details` 或 `--full` 时按既有语义展开日志首次快照（`--details` 增补问题/经验字段，`--full` 给出整段裁剪）。旧日志没有摘要时的有限提取同样只在显式详情时进行，并标明不完整；不为续接批量改写旧日志，也不要求每个追加段独立摘要。

没有命中当前主题时，默认只给最多 3 条有界历史来源定位（仅路径，明确标注非当前状态，`--details`/`--full` 可展开摘要），不默认展开任何快照或有限提取；不能把旧摘要当作最新进度，可在同一记录库内按已有来源有限读回当前记忆核对，仍不扩大成全量历史扫描。

默认最多 5 条当前主题、5 条相关待办及最多 5 条时间线/经验一行候选（时间线候选明确标注历史定位，不代表当前状态或建议）。需要深读时只展开最相关的 1～2 份事实来源；用于定位的索引不挤占事实依据额度，但其摘要结论仍需核对来源。每次展示通常不超过 80 行，不是会话累计行数硬限。普通新需求不检索，同一问题本轮不重复，除非出现新证据或路线变化。

当前摘要也可能过时。涉及文件、代码、版本或环境时定点核验；待验证经验标注“仅供核查，不作为执行建议”，其建议动作不作为有效推荐输出；已替代经验不进入候选。历史下一步不构成当前执行授权。缺依据时如实说明，必要时按检索说明限量查原始会话。

来源片段被截断、存在后续追加或认识冲突时，按[定点读取说明](search.md#在已定位来源中定点读取)先在所选文件内定位关键词行号，再读相邻上下文。固定首尾窗口不能排除中段纠正；这不要求每次续接额外search，也不扩大来源数量或全库扫描。
