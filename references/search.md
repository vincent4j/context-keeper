# 查找相似经验

## 步骤

1. **判断是否已有当前会话上下文**
   - 当前会话已有需求、报错、测试失败、文件路径、模块名、字段名、接口名、模型名或实现过程时，直接自动提取关键词。
   - 如果新会话几乎没有线索，再提示用户描述问题或粘贴报错。

2. **自动提取关键词**
   - 优先提取：模块名、业务名词、错误码 / 报错、字段名、接口名、文件名、类名 / 函数名、模型名、测试名、合同 ID。
   - 先覆盖最近用户需求和当前卡点，再补充已触碰文件和已运行命令中的关键词。
   - 提取后简短说明：`我会基于当前会话自动检索这些线索：...`

3. **检索 `docs/memory-keeper.md`**
   - 不存在时提示尚无项目记忆，建议先执行保存操作。
   - 优先运行脚本获取限量命中：

   ```bash
   scripts/context_keeper_probe.py search --root <repo> --query '<关键词1|关键词2|关键词3>'
   ```

   - 如果脚本不可用，再用全文件搜索覆盖历史条目，但不全文加载：

   ```bash
   rg -n -m 20 '<关键词1|关键词2|关键词3>' docs/memory-keeper.md
   ```

   - 命中超过 20 行时，先用模块名、错误码、文件名、接口名或模型名收窄。
   - 优先读取最多 5 条命中的完整条目。
   - 条目不足以判断时，才按 `详见` 链接读取对应 worklog 的相关段落：

   ```bash
   rg -n -m 8 -C 1 '<关键词>' docs/worklog/<file>.md
   sed -n '<start>,<end>p' docs/worklog/<file>.md
   ```

4. **输出命中结果**

   ```text
   命中 N 条相似经验：

   1. YYYY-MM-DD - [标题]
   模块：...
   命中线索：...
   适用经验：...
   合同候选：...
   详见：...

   本轮建议：
   - ...
   ```

5. **生效边界**
   - 命中内容是历史经验和合同候选，只用于提醒排查方向和避免重复踩坑。
   - Context Keeper 单独安装时，不把命中内容称为"生效合同"或"硬约束"。
   - 如果项目另有 PRD / 合同系统，真正硬约束以项目生效合同为准。
